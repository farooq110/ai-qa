A test is an ordered list of steps. The browser performs them top to bottom and the test passes only if every step succeeds. The **first failing step stops the test**.

This page covers the editor. For every action, how targets resolve, and timeouts, see the [Test steps reference](/docs/reference/test-steps).

## Anatomy of a step

<Shot src="/images/writing-test-steps/step-anatomy.png" alt="A step row with its controls numbered" width={1692} height={537} />

| # | Control | Does |
| --- | --- | --- |
| 1 | Drag handle | Reorder by dragging. |
| 2 | Position | Execution order. |
| 3 | Action | What the browser does. |
| 4 | Target | Where it applies; meaning depends on the action. |
| 5 | Move arrows | Nudge one position. |
| 6 | Remove | Delete the step. |

Some actions add a **value** field, a condition dropdown, or region fields.

## Reordering and inserting

Hover between two rows and click **Insert step**; drag the handle to reorder. **Add step** always appends a click at the bottom.

<Shot src="/images/writing-test-steps/insert-add-step.png" alt="The hover-revealed Insert step button between two rows, with Add step below" width={1756} height={549} />

<Shot src="/images/writing-test-steps/drag-reorder.png" alt="A step row highlighted as the drop target while reordering" width={1756} height={601} />

You can also [record steps in a browser](/docs/test-cases/recording-steps) instead of typing them.

## Saving

<Shot src="/images/writing-test-steps/save-footer.png" alt="The editor footer with the Cancel and Create test case buttons" width={1764} height={158} />

Saving needs a title and a target on every step. New tests are **Pending review**; an edit creates a new version that returns to review.
